# Collect the BEA schedule as an independent calendar source

The dashboard publishes static JSON to GitHub Pages. A cloud runner must collect each source before publication. BEA's [official calendar page](https://www.bea.gov/news/schedule/icalendar) links a keyless [JSON release schedule](https://apps.bea.gov/API/signup/release_dates.json). The schedule includes complete release timestamps with UTC offsets. It supplies planned release times, without actual values or forecasts.

BEA uses its own `bea_calendar` provider domain. `CalendarCollector` combines that domain with the existing earnings and FRED/Federal Reserve domains. The registry retains its first-success fallback behavior, retries, host limits, circuit breaker, and last-good cache. Configuring BEA as another `economic` fallback would omit its events whenever FRED succeeds. Adding BEA requests inside the FRED provider would hide its independent failures and host budget.

Every economic provider returns one normalized `EconomicRow.datetime` in UTC. FRED and Federal Reserve adapters convert their configured Eastern times before returning rows. The BEA adapter validates the external JSON, rejects timestamps without an explicit offset, and normalizes each instant once. A deterministic title-and-instant ID removes duplicate BEA records across retries. The collector keeps the existing FRED event when a BEA event has the same title and instant. Corporate Profits and GDP remain separate events even when they share a release time.

The economic cache key is `economic_v2_<horizon>d`. Entries under the old `economic_<horizon>d` key lack FRED and FOMC completeness metadata. The registry does not read or quarantine files under the old key. New-key entries use the UTC row shape. The registry checks their age, schema, and replay validity. It quarantines incompatible entries under the new key.

`CalendarDataset.source_status` records the last result for each logical source. A successful fetch with no events is `empty`. Failure, fallback, or cache replay is `degraded`. A feed omitted from the provider registry is `not_configured` and does not count as a failed upstream request. The calendar page displays these states and their check timestamps. The shared `sources.json` projection continues to describe aggregate dataset health, as required by the existing freshness consistency check.

The approved public-source policy grants BEA ownership of `calendar`. The current policy allows one owner for this dataset, so approved-source runs collect BEA without earnings or FRED/Federal Reserve requests. The page names those unconfigured sources. Adding another approved calendar source requires a later policy change rather than an implicit expansion of this grant.

The calendar's expected update interval is 15 minutes, matching the configured cloud schedule. `generated_at` and each source's `checked_at` describe the dashboard check. They do not describe when BEA changed its release plan. BEA's offset-free `file_last_updated` and HTTP `Last-Modified` carry different source-file timestamps, so the collector leaves the global mixed-source `source_updated_at` unset.

BEA's [copyright FAQ](https://www.bea.gov/help/faq/147) states that its information is public domain unless indicated otherwise. The public-source grant records that status. The page also displays the non-endorsement notice required by the [BEA API terms](https://apps.bea.gov/api/_pdf/bea_api_tos.pdf). English source titles stay unchanged in the data. The page translates all 33 release titles present in the inspected schedule into Chinese and uses the existing localized fallback for a future unknown title.
