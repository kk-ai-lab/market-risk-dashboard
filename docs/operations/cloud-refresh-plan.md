# Cloud refresh plan

Status: publisher code and a 15-minute cron are implemented on this branch. The public `cloud-state` branch now contains the three validated empty ledgers and is protected against force pushes and deletion. `PAGES_LEGACY_BOOTSTRAP_CONFIRMED=true` is configured. No GitHub publication run has succeeded; GitHub will not run the schedule until the workflow is merged to the default branch, `main`.

## Target and delivery constraints

Attempt collection every 15 minutes from cloud infrastructure, recompute the risk and dashboard from one coherent set of inputs, and publish a validated Pages generation. An attempt is not a guarantee that sources publish or the scheduler runs every 15 minutes. Show source observation times and missing, delayed, or degraded data independently of the pipeline generation time. Macro releases and daily market closes have their own cadence.

When the publication checkpoint is empty, first publication is blocked unless the repository variable `PAGES_LEGACY_BOOTSTRAP_CONFIRMED` is explicitly set to `true`, even when the known legacy probes return 404. The probes cannot enumerate every file in a static Pages site. Confirmation replaces any legacy public data with a generation collected from approved sources; it does not import legacy history. An existing `/data/current.json` pointer without matching checkpoint state always blocks and requires a checkpoint migration.

GitHub Actions scheduled workflows run from the default branch and may be delayed or dropped. This repository currently deploys both `main` and `dev` to the same Pages site. Scheduled collection and code deployments therefore need one serialized publication owner, plus a decision on the default-branch rollout. See [GitHub's schedule documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Source review before cloud publication

- The [FRED terms](https://fred.stlouisfed.org/legal/terms/) restrict API-related caching, archiving, and providing stored content to third parties. They also require separate consideration of third-party data rights. Individual series such as [DGS2](https://fred.stlouisfed.org/series/DGS2) and [DGS10](https://fred.stlouisfed.org/series/DGS10) carry public-domain labels; distinguish those underlying data rights from the terms governing use of the FRED service. The existing public JSON and pipeline need a source-by-source review; adding a public state branch or Actions cache is not assumed to grant rights. Identify replacement original sources or obtain applicable permission before expanding this usage.
- The Bureau of Labor Statistics permits reuse of its [public-domain material](https://www.bls.gov/opub/copyright-information.htm). Its [API limits](https://www.bls.gov/developers/api_FAQs.htm) require monthly series to be batched and checked less often than every 15 minutes on the unregistered tier. CPI and core CPI require a year-over-year calculation from consecutive annual observations; payroll requires a month-over-month change. Observation periods are not release timestamps. These series cover only part of the existing macro dataset.
- An opt-in local BLS integration uses `DATA_BLS_ENABLED=true` and stores its ledger under `DATA_ARTIFACTS_DIR/bls/snapshot.json`. It attempts a single batch per UTC day when processes share this ledger and its lock. The manual shadow run uses an isolated local ledger for one invocation. Production cloud mode uses the provisioned shared checkpoint; its first real BLS request and recovery still need cloud-run verification. When a BLS series is missing, it stays missing rather than silently falling back to FRED.
- The checkpoint adapter uses GitHub's `createCommitOnBranch` with `expectedHeadOid` to reject writes based on an obsolete branch head. A timeout or ambiguous response does not establish whether the write happened; reconcile by reading the branch before taking another action. This check cannot detect an intervening A → B → A branch reset. `cloud-state` was provisioned on 2026-11-15 with empty publication, BLS, and Treasury ledgers, then protected against force pushes and deletion. The scheduled publisher still requires a successful cloud run and Pages readback.
- An independently enabled cloud BLS mode records a unique pending reservation on that checkpoint before requesting the API. It reuses or degrades previously verified observations if a later operation fails; it never silently replaces a damaged remote ledger with a local one. This limits attempts per recorded UTC budget day, but a runner suspended after its clock check can resume across midnight: a client-side ledger alone cannot strictly guarantee the physical request time. The checkpoint is provisioned; the complete workflow must be verified before scheduling it.
- [CoinGecko distinguishes public display from redistribution](https://support.coingecko.com/articles/1043089972-what-are-the-differences-between-commercial-and-custom-licenses). Public JSON downloadable by other users may require a separate license; attribution alone does not establish redistribution rights. Confirm the intended usage with the provider, or use an appropriately licensed alternative.
- [Coin Metrics Community](https://docs.coinmetrics.io/service-and-support/coverage) offers its Community API under [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/), which permits redistribution subject to noncommercial use, attribution, a license link, and disclosure of modifications. The site owner confirmed that this site is noncommercial on 2026-11-15; required attribution must accompany publication. Its [ReferenceRateUSD](https://docs.coinmetrics.io/coin-metrics-prices/coin-metrics-prices/reference-rate-metrics) is a computed market-wide reference rate, not a specific exchange's last trade. A live unauthenticated BTC/ETH query returned one-minute observations; a 15-minute job can sample these while preserving their source timestamps. Community historical-window documentation differs, so do not promise fixed historical coverage.
- The [yfinance project](https://github.com/ranaroussi/yfinance/blob/main/doc/source/index.rst) describes Yahoo Finance data access as intended for personal use. Confirm publication rights before automating public redistribution. Its current adapter also derives quotes from daily histories; a 15-minute job would not make those prices intraday.
- Treasury publishes an [official daily yield XML feed](https://home.treasury.gov/treasury-daily-interest-rate-xml-feed). The specific [Daily Treasury Yield Curve Rates dataset](https://catalog.data.gov/dataset/interest-rate-statistics-daily-treasury-yield-curve-rates) is listed as CC0 by Data.gov; this does not establish rights for other Treasury datasets or underlying dealer quotes. The feed supplies 2-year and 10-year CMT values and is a candidate for those specific indicators, not all FRED series. Treasury's [methodology](https://home.treasury.gov/policy-issues/financing-the-government/interest-rate-statistics/treasury-yield-curve-methodology) describes daily indicative bid-side inputs and a methodology change in December 2021. Observation dates are not release timestamps and these yields are not intraday prices. The FRED DGS2 and DGS10 series have the same economic definition, but their release timing can differ; compare overlapping historical observations before combining sources. The Federal Reserve Board [plans to retire its DDP interface](https://www.federalreserve.gov/datadownload/Choose.aspx?rel=H15), so do not build a long-lived integration around that interface without a migration plan.
- As one market-data comparison, Massive says its [free US stock tier provides prior-day data](https://massive.com/knowledge-base/article/on-the-free-basic-plan-when-can-i-pull-the-previous-trading-days-data) and [individual subscriptions do not cover redistribution](https://massive.com/knowledge-base/article/how-can-i-redistribute-massives-market-data). It therefore does not establish a free solution for public intraday stock data.

## Shadow collection evidence (2026-11-15)

An isolated local run used only the approved Coin Metrics, BLS, and Treasury adapters; it wrote to
`/tmp/mrd-approved-pipeline-resume-20261115/` and did not touch `public/data` or deploy anything.
The collector completed in 111.9 seconds (`ok=true`, `clean=false`). BLS supplied four monthly
series. Treasury supplied current-year 2Y/10Y CMT observations, while its absent cross-runner
history made both series degraded. Equities, sectors, commodities, calendar, and news were
explicitly omitted. The output contained no failed datasets and passed the local Python/Node
candidate validators, so an immutable local generation was staged.

The risk evidence state was `insufficient_evidence`, effective coverage was 10%, and the
provisional score interval was 6.4–96.39. The point estimate is not suitable as a production
aggregate. The candidate is a format and integration proof only: it is not the live Pages data,
the GitHub runner has not executed it, and no 15-minute publisher run has been verified.

1. Inventory every published field and source, its original owner, permitted display and storage, update cadence, and rate limits. Mark unverified sources unavailable for the new public publisher; do not publish raw caches as a shortcut.
2. Replace or explicitly license sources and split daily historical inputs from genuinely intraday observations. Carry history forward with its actual observation time, not the current job time. Bound concurrency and request volume, and test missing keys, cold starts, and provider outages.
3. Keep a durable, versioned checkpoint only for data that may be stored and published. A candidate includes a generation ID, parent ID, code revision, source provenance, and hashes. Validate candidate contracts and coverage before switching the published generation. Ensure failure preserves the last valid generation.
4. Use generation-pinned client URLs or equivalent so a reader cannot combine files from two deployments. Serialize scheduled and code-only publication; code deployment must not replace newer data with the repository's older snapshot.
   New clients read generation-pinned data. Legacy mutable URLs remain available as compatibility projections: new reason codes map to the nearest old code; risk snapshots are withheld unless evidence is complete and every dimension trend is in the old enum; crypto is withheld when an asset lacks the timestamp required by the old schema; and a risk history file is withheld if any point lacks complete evidence. An old open client can temporarily lose a risk panel, history chart, or crypto dataset when its schema cannot represent the published evidence; it must never display an unsupported score or a gap-free trend as valid.
5. The isolated shadow workflow and serialized publisher are implemented. The shadow workflow does not restore cloud checkpoints or publish Pages. Run a manual publication from `dev`, inspect its artifact and live Pages readback, and verify checkpoint transitions before promoting the cron to `main`.
6. Expand risk inputs with point-in-time historical validation before changing production weights. Continue bilingual, responsive UI work and expose coverage and proxy limitations.
